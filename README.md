# Тусовка

Вебзастосунок для публічних і приватних подій з обмеженою кількістю місць. Користувачі створюють події, записуються, скасовують участь і коментують. Автор бачить список учасників і керує запрошеннями.

## Локальний запуск

Потрібен Python 3.12 або новіший. У каталозі проєкту виконайте команди для своєї системи.

**Windows PowerShell**

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

**Linux або macOS**

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py runserver 127.0.0.1:8000
```

Відкрийте [локальну Тусовку](http://127.0.0.1:8000/). Почніть із реєстрації та створіть подію. Для перевірки приватної події згенеруйте запрошення на її сторінці й відкрийте посилання в іншому браузерному профілі. Прийміть запрошення після входу під другим акаунтом. Локальна база `db.sqlite3` створюється під час міграції.

### Запуск для автоматичної перевірки

В ізольованому середовищі з Python 3.12 або новішим виконайте з кореня репозиторію:

```sh
python -m pip install -r requirements.txt
python manage.py migrate --noinput
python manage.py runserver 0.0.0.0:8000 --noreload
```

Після запуску перевірте `GET /` на порту `8000`. Для перевірки через `localhost` або `127.0.0.1` змінні середовища й початкові облікові дані не потрібні. Нові акаунти можна створити на `/register/`.

## Автотести

В активованому віртуальному середовищі виконайте `python manage.py test`. У Windows також можна запустити `.\.venv\Scripts\python.exe manage.py test`.

Тести перевіряють акаунти, український пошук, права автора, приватність сторінок і обкладинок, повторне прийняття й ротацію запрошень, зміну видимості, видалення та конкурентний запис. Вони використовують окрему тимчасову SQLite-базу.

## Змінні середовища

Для локального запуску значення за замовчуванням достатні. `.env.example` показує назви змінних. Задайте потрібні значення в оболонці або в середовищі хостингу. Django в цій конфігурації читає змінні з процесу.

| Змінна | Локальне значення за замовчуванням | Для публічного сервера |
| --- | --- | --- |
| `TUSOVKA_DEBUG` | `1` | Задайте `0`. |
| `TUSOVKA_SECRET_KEY` | Локальний ключ розробки | Задайте довгий випадковий секрет. Обов’язковий з `TUSOVKA_DEBUG=0`. |
| `TUSOVKA_ALLOWED_HOSTS` | `localhost,127.0.0.1,[::1]` | Домен або список доменів через кому, без схеми. |
| `TUSOVKA_ORIGIN` | Порожньо, посилання будується з локального запиту | Задайте HTTPS-адресу, наприклад `https://events.example.org`. |
| `TUSOVKA_DB_PATH` | `db.sqlite3` у проєкті | Абсолютний шлях до файлу на постійному диску з правом запису. |
| `TUSOVKA_TRUST_PROXY` | Вимкнено | Задайте `1` лише за довіреним проксі, який перезаписує `X-Forwarded-Proto`, а прямий доступ до WSGI-сервера закритий. |

Для публічного запуску застосуйте міграції, виконайте `python manage.py collectstatic --noinput` і `python manage.py check --deploy`. Запустіть `config.wsgi:application` під WSGI-сервером, налаштуйте HTTPS і видачу `/static/` з каталогу `staticfiles/`. Використовуйте один екземпляр застосунку з постійним диском і резервними копіями бази. На проксі обмежте частоту запитів до `/login/` і `/register/`, розмір HTTP-запиту до 4 МБ та маскуйте токени в журналах маршруту `/invite/`.
